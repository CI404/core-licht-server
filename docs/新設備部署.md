# 新設備部署

把這套離線伺服器用在**其他 Android 設備**（另一台模擬器、真機、平板）。

---

## 一、先理解：為什麼要改 OBB

遊戲客戶端啟動時會讀 OBB 內的 `assets/UrlList_Android.txt`，決定「去哪台伺服器抓資源」。
原廠寫的是 `https://pfdh-cdnres.rhinosgamestw.com`（**已下線**），所以要改成你的電腦。

### OBB 裡只有「一份」UrlList（但很容易找錯地方）

| 檔案 | 內部位移 | 大小 | 說明 |
|---|---|---|---|
| `patch.138.com.tw99.no23.an.obb` | **1519062275** | 598 bytes | ★ **UrlList 在這裡** |
| `main.138.com.tw99.no23.an.obb` | — | — | 沒有 UrlList（`1528431122` 是 `assets/Zero/Lua/lua.ab`） |

> 實測證據（用 `adb exec-out dd` 直接撈位元組）：
> ```
> patch @ 1519062275 → {"baseUrl":"http://10.0.2.2:8080/cdnconfig_{0}/",...   ← UrlList
> patch @ 1519062233 → 檔名區塊 + UrlList 資料（local CRC 位置）
> main  @ 1528431122 → "UnityFS..."            ← 這是 lua.ab，不是 UrlList
> main  @ 1528431084 → "assets/Zero/Lua/lua.ab" + lua.ab 資料
> ```
> **所以只要改 `patch` OBB 就夠了。**

### 好消息：不需要 root

實測 MuMu 的 OBB 權限是 `-rw-rw-rw- ... ext_obb_rw`，
而 `adb shell` 的身份 `uid=2000(shell)` **就在 `ext_obb_rw` 群組裡**（gid 1079）。

→ **可以直接 `dd` 寫入，不需要 root、不需要 `su`。**

真機通常也是這個權限（Android 對 OBB 目錄的標準設計）。
若你的裝置例外，見本檔最後「四、無寫入權限的替代做法」。

## 二、目標設備要先有遊戲

### 2-1 安裝 APK

```cmd
adb install "核芯：利希特_0.1.38_APKPure.apk"
```

若你手上是 `.xapk`（APKPure 格式，其實是 zip）：
1. 改名成 `.zip` 解開
2. 裡面會有多個 `*.apk`（base + split），全部一起裝：
```cmd
adb install-multiple base.apk config.arm64_v8a.apk
```
3. 把 `Android\obb\` 內的兩個 OBB 複製到裝置同一路徑：
```
/sdcard/Android/obb/com.tw99.no23.an/
```

### 2-2 驗證 OBB 就位

```cmd
adb shell ls -l /sdcard/Android/obb/com.tw99.no23.an/
```
應看到：
```
main.138.com.tw99.no23.an.obb     (1538811147 bytes)
patch.138.com.tw99.no23.an.obb    (1684642455 bytes)
```

> 建議**先完整啟動一次遊戲**（就算連不上），讓它建立必要的目錄結構。

## 三、標準流程（模擬器 / 有寫入權限的真機）

### 3-1 設定電腦這邊

1. 開 `config\server.json`，把 `host` 改成**這台裝置能連到的位址**：

| 裝置 | host |
|---|---|
| 同電腦的 MuMu / 雷電 | `10.0.2.2` |
| 真機（同 Wi-Fi） | 電腦區網 IP，例如 `192.168.1.100` |
| 另一台電腦上的模擬器 | 那台電腦的區網 IP |

2. 啟動伺服器：`scripts\1-啟動伺服器.bat`

### 3-2 產生並部署 UrlList

```cmd
scripts\3-產生UrlList.bat
scripts\4-部署到設備.bat
```

`4-部署到設備.bat` 會引導你選裝置、寫入、並清除快取。

> `4-部署到設備.bat` 已設定正確的 patch OBB 位移（`1519062275`），
> 不需要手動處理。以下指令僅供你手動排查時參考。

### 3-3 手動指令（排查用）

```cmd
adb push output\UrlList_Android.txt /data/local/tmp/ul.txt

adb shell "dd if=/data/local/tmp/ul.txt of=/sdcard/Android/obb/com.tw99.no23.an/patch.138.com.tw99.no23.an.obb bs=1 seek=1519062275 count=598 conv=notrunc"
```

### 3-4 清除快取並啟動

```cmd
adb shell pm clear com.tw99.no23.an
```

**這一步不能省** —— Unity 會把讀過的資源快取在
`/sdcard/Android/data/com.tw99.no23.an/files/UnityCache/`，
不清理就會繼續用舊的 UrlList。

## 四、無寫入權限的替代做法

若 `4-部署到設備.bat` 回報寫入失敗（權限不足），改成「拉出來改、推回去」：

### 4-1 拉出 OBB（只需 patch 那份）

```cmd
adb pull /sdcard/Android/obb/com.tw99.no23.an/patch.138.com.tw99.no23.an.obb  D:\obb\
```
（約 1.68 GB，需要一點時間）

### 4-2 在電腦上就地改寫（用本專案附的工具）

```cmd
python\python.exe patch_obb.py D:\obb\patch.138.com.tw99.no23.an.obb --dry-run
```

先 `--dry-run` 確認位移正確，再實際寫入（會自動備份成 `.bak`）：

```cmd
python\python.exe patch_obb.py D:\obb\patch.138.com.tw99.no23.an.obb
```

或手動用 PowerShell（等同效果）：

```powershell
$obb  = "D:\obb\patch.138.com.tw99.no23.an.obb"
$new  = [System.IO.File]::ReadAllBytes("output\UrlList_Android.txt")   # 598 bytes

$fs = [System.IO.File]::Open($obb, 'Open', 'ReadWrite')
$fs.Seek(1519062275, 'Begin') | Out-Null
$fs.Write($new, 0, $new.Length)
$fs.Close()
```

### 4-3 推回去

```cmd
adb push D:\obb\patch.138.com.tw99.no23.an.obb /sdcard/Android/obb/com.tw99.no23.an/
adb shell pm clear com.tw99.no23.an
```

> 若 `push` 也失敗，代表該裝置的 OBB 目錄真的不給寫。
> 這種情況下**唯一**的辦法是 root，或改用支援的模擬器。

## 五、多裝置同時使用

可以！只要**同一個區網**，多台裝置可以同時連同一組伺服器。

注意事項：
- `config\server.json` 的 `host` 要填**所有裝置都能連到的位址**（通常是電腦的區網 IP）
- 每台裝置都要各自跑一次 `4-部署到設備.bat`（各自的 OBB 要各自改）
- 所有人的帳號資料會**共用同一份**（目前沒有存檔隔離，屬正常）

## 六、防火牆

**最常見的「連不上」原因。**

第一次啟動伺服器時，Windows 會跳出「是否允許應用程式通過防火牆」，
**兩個都要勾「私人網路」**（Python 與 Node）。

若當時按了「取消」，手動補救：

```powershell
# 以系統管理員身分執行 PowerShell
New-NetFirewallRule -DisplayName "Licht Server 9001" -Direction Inbound -Protocol TCP -LocalPort 9001 -Action Allow
New-NetFirewallRule -DisplayName "Licht CDN 8080"    -Direction Inbound -Protocol TCP -LocalPort 8080 -Action Allow
```

**驗證方式**（從目標裝置的瀏覽器打開）：
```
http://<你的host>:8080/android_tw/stable/release/config.txt
```
能下載到內容 = 網路通了。

## 七、疑難排解對照表

| 症狀 | 最可能原因 | 檢查 |
|---|---|---|
| 遊戲卡「評估中」 | CDN 沒起來 / 防火牆擋住 | 瀏覽器測 `:8080/...config.txt` |
| 連到伺服器但卡登入 | `host` 填錯 | 裝置瀏覽器測 `:9001` |
| 改了 UrlList 沒生效 | 沒 `pm clear` | 再跑一次清除 |
| 寫入 OBB 失敗 | 權限不足 | 見第四節 |
| 主界面數值不對 | 伺服器讀到舊配置表 | 確認 `data\decoded` 是 365 檔 |
| `adb devices` 空的 | 沒開 USB 偵錯 | 開發者選項 → USB 偵錯 |
