# 適格體圖鑑 — 編號對照與重建指南

> **本檔來源**：2026-10-10 由使用者發現的關鍵機制。
> 使用者原話：「在適格體界面中，點擊每個適格體，可以發現界面中上方有角色對應的編號。」
>
> **這個發現的價值**：它把「遊戲內角色」和「反編譯出來的立繪檔」用一個**純數字**串起來了。
> 有了對照，就能**純靠配置表 + 資源檔重建一個適格體圖鑑**，不需要執行遊戲。

## 1. 核心機制（一句話）

> **適格體界面上方顯示的編號 = `DataTable_children_skin.head_new`**
> **該編號直接就是立繪檔名：`card_pic_<head_new>.png`**

### 實測驗證（100% 命中，61/61）

| 界面顯示編號 | `children_skin` 的 `id` | 角色名 | 畫師 | 對應檔案 |
|---|---|---|---|---|
| `300501` | `1430050001` | 林檎 | 薩摩ssssssamo | `card_pic_300501.png` |
| `600901` | `1460090001` | 慈夏正 | 反樸還淳淳 | `card_pic_600901.png` |
| `600204` | `1406600204` | 微光 | GZ1605 | `card_pic_600204.png` |
| `100104` | `1406100104` | 厄莉希 | 兔扎特 | `card_pic_100104.png` |
| `700101` | `80004` | 德拉普爾 | 哈嘍啊 | `card_pic_700101.png` |

**注意**：`head_new` 與 `id` 是**兩套完全不同的編號**，不要混淆。

```
id      →  10 位數（如 1430050001），是資料庫主鍵
head_new→  6 位數（如 300501），是【美術編號】，對應檔名
skin_pic→  5 位數（如 10101），是另一套【卡面編號】，對應 card_<skin_pic>.png
```

## 2. 兩套編號系統的完整關係

`DataTable_children_skin`（333 筆）每筆都有這三個欄位：

```json
{
  "_key": "1430050001",          // = id
  "name": "林檎",                 // 角色名
  "painter": "薩摩ssssssamo",     // 畫師
  "head_new": "300501",           // ★ 6 位美術編號 → card_pic_300501.png
  "skin_pic": "10101",            // ★ 5 位卡面編號 → card_10101.png（在 children 表也有）
  "model": ...,                   // 戰斗模型
  "model_island": 12010011,       // 空島模型
  "spine_id": 10000000,           // Spine 骨骼 id
  "model_scale": 125,
  "photo_para": [1.5, -344, 0, 0.7],   // 立繪排版參數（x, y, 縮放基準, scale）
  "photo_para1" ~ "photo_para7",       // 各部位微調
  "skill_show": [[20035101, 1], ...],
  "anim_effect_kd": [["Kd_Sleep", 410003], ...]
}
```

**三個編號的命名後綴規律**（觀察值）：

```
1xxxxxxx   → 一級角色（100101 ~ 101xxx 區段）
2xxxxxxx   → 二級角色
...
8xxxxxxx   → 八級角色
14xxxxxxx  → 皮膚 id（14 開頭）
80004 / 1001 … → 特殊角色（NPC / 初始角色）
```

### 模型設定檔格式（`*.config.json`）

```json
{
  "type": 9,
  "controllers": { "intimacy_system": {}, "slot_opacity": {}, "slot_color": {} },
  "hit_areas": [ { "name": "bone472", "id": "bone472", "width": 2.0, "height": 2.0 } ],
  "motions": {
    "idle": [ { "file": "idle" } ],
    "tap":  [ { "file": "idle1" } ]
  },
  "options": { "edge_padding": false },
  "skeleton": "TextAsset/spine_a04004_01.skel",
  "atlases": [{
    "atlas": "TextAsset/spine_a04004_01.atlas",
    "tex_names": ["spine_a04004_01", "spine_a040042"],
    "textures": ["Texture2D/spine_a04004_01.png", "Texture2D/spine_a040012.png"]
  }]
}
```

**重點欄位**：
- `hit_areas` → 可點擊區域（點角色會有反應，如 `touch` 互動）
- `motions.idle` / `motions.tap` → 待機與點擊動作
- `controllers.intimacy_system` → **親密度系統**（好感度影響動作）
- `type: 9` → 這個值在 `children_skin` 或其他表可能有對應定義，**尚未確認**

## 6. 重建適格體圖鑑的可行路徑

### 6.1 資料來源（全部已具備）

| 資料 | 位置 | 狀態 |
|---|---|---|
| 皮膚主表 | `raw/decoded/DataTable_children_skin.rows.json` | ✅ 333 筆 |
| 角色主表 | `raw/decoded/DataTable_children.rows.json` | ✅ 113 筆 |
| 立繪小圖 | `E:\核心：利希特\核心live2d\**\card_pic_*.png` | ⚠️ 61/333 |
| 卡面大圖 | `...\Sprite\card_*.png`、`...\Texture2D\card_*.png` | ⚠️ 8 筆 |
| Spine 模型 | `...\<模型名>\TextAsset\*.skel` | ⚠️ 23 套 |
| 匯出工具 | `server/tools/enum_atlas.py` | ✅ 本專案 |

### 6.2 建議做法

```
① 用 tools/enum_atlas.py 匯出 JSON（已附在 docs/適格體圖鑑-資料.json）
② 前端（純靜態 HTML + JS 即可）：
     - 讀 JSON
     - 卡片列表：<img src="card_pic_<head_new>.png"> + name + painter
     - 詳情頁：顯示 photo_para 排版參數的立繪、skill_show、皮膚列表
③ Spine 播放：用 spine-webgl / pixi-spine 載入 .skel + .atlas + .png
     - 動作：idle（待機）、tap（點擊）
     - 互動區域：hit_areas（可做「點擊角色有反應」）
④ 補齊覆蓋率：解出其餘 AssetBundle 裡的 card_pic_*.png
     （OBB 內 CardPicIcon / CardTexture，需用 AssetStudio 之類工具解）
```

### 6.3 為什麼這個發現讓重建變可行

> **沒有這個對照，就只能靠「角色名」猜檔名 —— 而檔名是數字。**
> **有了 `head_new`，`遊戲內角色 ↔ 立繪檔` 就是一次字典查詢。**

這也是為什麼值得寫進知識庫：它是**資料層的最後一塊拼圖**。

## 8. 附帶釐清：為什麼適格體界面顯示 14 張一樣的「瞳」

使用者先前回報「適格體界面顯示 14 張重複的瞳」，一度以為是 bug。

**真相**：`DataTable_children_skin` 中「瞳」有 **32 個皮膚**（`id=101`, `102`, `103`…各為不同職業/服裝）。
客戶端把**所有 skin 都列出**，所以看到多張同名卡片是**正常設計**，不是資料錯誤。

```
瞳 : 32 個皮膚   ← 最多的角色
舊影 : 7
阿德涅 : 5
妮瑟琳 / 桑娜 / 德拉普爾 : 各 4
（96 個不重複角色名，共 333 個皮膚）
```

⚠️ 但先前那次「14 張全部沒有立繪」**確實是資料異常**（伺服器推了 4 個配置表查不到的假 skin id），已在修復 #1 處理（`valid_skin_ids()` 白名單）。
