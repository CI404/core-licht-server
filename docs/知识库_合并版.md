### 0.5.1 ⭐ 本輪最重要發現：`p_children.type` 的雙消費方衝突

**`CardDefine.CardTypeIndex` 完整值**（★ **第一行 `Common` 極易漏讀**，我漏過一次）：

```
Common = 1     ← ★ 在 SETFIELD 1 2 K[3]（其他都在 SETFIELD 1 46..53）
Secret = 2   Assist = 3   Teach = 4   Explore = 5
WarFight = 6  Hero = 7    HeroTeach = 8   PVP = 9
```

**取得方法**（可複用）：`x.Module.Card.CardDefine.dis.txt` 裡，
`SETFIELD 1 <常量索引> K[<值常量索引>]` 的序列 —— 表索引是**常量索引**，
值要再去 int 常量表查。以 `SETFIELD 1 51 K[39]` 為例：常量索引 51 → `"Hero"`，
K[39] → int `7`。

**兩個消費方對同一個 `p_children.type` 的要求相反**：

| 消費方 | 客戶端程式碼 | 要求 |
|---|---|---|
| **適格體卡列表** | `CardModel.GetCardBagDic(cardList, type)`（proto 0.21）L23-40：<br>`for _, card in pairs(cardList) do if card.type == type then insert end end`<br>呼叫端傳 `CardTypeIndex.Common` | **1** |
| **助理界面** | `HeroModel.UpdateHeroInfo`（proto 0.3）L101-108：<br>`hero.cardType = CardModel:GetCardInfoById(hero.children_id).type`<br>`GetHeroInfoBySysId` 要求 `cardType == CardTypeIndex.Hero` | **7** |

**★ 解法（單卡特判）**：
```python
# player_data.py build_maxed_child
m.type = 7 if cid == init_hero_sys_id() else 1     # init_hero = 1001
```
**為什麼可行**（三個已證事實）：
1. `DataTable_config['init_hero'].value == 1001`
2. `CardModel.GetCardInfoById(id)` 按 **`card.id`** 查找（proto 0.46）
3. ⇒ 助理只查 `id=1001` 這一張卡 ⇒ 只有它需為 7；其餘 105 張保持 1 讓適格體列表非空

**走過的彎路（勿重蹈）**：
| 做法 | 結果 |
|---|---|
| 106 張全部 `type=7` | 助理 ✓ 恢復，但**適格體清單變空**（顯示「暫無適格體」） |
| 106 張全部 `type=1` | 適格體 ✓，但**助理白屏** |
| **只讓 `id=1001` 為 7** | ✅ **兩者皆正常**（使用者實測確認） |

**另註**：`CardModel.UpdateCardInfo`（proto 0.9）L46-53 用
`card.isHadRedPoint = (card.type == CardTypeIndex.Common)` —— **只影響紅點，不影響是否入列**。
（我一開始誤判它是「是否入列」的判定，導致推理繞遠路。）

## 3. 协议规格 `[REF][APK]`（来自 `SNPacketData` 反汇编）

**证据来源**：`libil2cpp.so` (arm64) 反汇编
`SNPacketData.GenC2SPacket @ 0x1585D1C`、`ProcessS2CPacket @ 0x1585EE4`、
`SNBuffer.*`、`SNTCPClient.*`；以及 `global-metadata.dat` → `XorCode._passArr`

```
C2S: [u16 BE len = 总长-2][u16 BE uniq][u8 sId][u8 mId][body XOR passArr[(uniq+i)&0xFF]]
S2C: [u16 BE len = 总长-2][u8 sId][u8 mId][u8 zflag][body XOR passArr[((sId*16+mId)+i)&0xFF]]
       ↑ 两个方向 XOR 种子不同！
连线建立时客户端先送裸 2 bytes 01 02 → 必须丢弃，不可回送
zflag != 0 ⇒ body 是 zlib
```

**两条铁则**：

2. **`26_2 scenario_enter_c2s` 没有 s2c** —— 它是通知型消息，不回是对的

**实现**：`server\lichter_wire.py`（含 256 字节 `PASSARR`、`FrameReader`、
`decode_c2s` / `encode_s2c` / `load_pool`），**自检 round-trip 通过** `[本区]`

### 4.4 `TwoAryToObj` 契约 `[APK][本区]`

```lua
function TwoAryToObj(A, B, C)
    for _, row in ipairs(A) do            -- A = 行数据
        if type(row) == "table" then
            for _, k in ipairs(B) do      -- B = 字段名数组
                obj[k] = row[k] or "unknown"
            end
        end
    end
end
```

调用点：`TwoAryToObj(data.region_key, GetYyb(811), data.region_list)`

**客户端报错形态**（可用于诊断）：
```
數據體不是table類型 valueIndex=N          → 列表元素不是 table
數據體中缺失指定key值 valueIndex=1 key=X  → 行对象缺字段 X
```

**`GetYyb` 查的是 `DataTable_lua_yyb`**（2499 条，非 `lang_txt`）。
`GetYyb(811)` = `'請求遊戲服列表返回獲取遊戲服列表'`（是**日志标签**，不是字段名）。
