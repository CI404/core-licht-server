### 0.5.1 ⭐ 本輪最重要發現：`p_children.type` 的雙消費方衝突

**`CardDefine.CardTypeIndex` 完整值**（★ **第一行 `Common` 極易漏讀**，我漏過一次）：

```
Common = 1     ← ★ 在 SETFIELD 1 2 K[3]（其他都在 SETFIELD 1 46..53）
Secret = 2   Assist = 3   Teach = 4   Explore = 5
WarFight = 6  Hero = 7    HeroTeach = 8   PVP = 9
```

**取得方法**（可複用）：`x.Module.Card.CardDefine.dis.txt` 裡，
`SETFIELD 1 <常量索引> K[<值常量索引>]` 的序列 —— 表索引是**常量索引**，
值要再去 int 常量表查。以 `SETFIELD 1 51 K[39]` 為例：常量索引 51 → `"Hero"`，
K[39] → int `7`。

**兩個消費方對同一個 `p_children.type` 的要求相反**：

| 消費方 | 客戶端程式碼 | 要求 |
|---|---|---|
| **適格體卡列表** | `CardModel.GetCardBagDic(cardList, type)`（proto 0.21）L23-40：<br>`for _, card in pairs(cardList) do if card.type == type then insert end end`<br>呼叫端傳 `CardTypeIndex.Common` | **1** |
| **助理界面** | `HeroModel.UpdateHeroInfo`（proto 0.3）L101-108：<br>`hero.cardType = CardModel:GetCardInfoById(hero.children_id).type`<br>`GetHeroInfoBySysId` 要求 `cardType == CardTypeIndex.Hero` | **7** |

**★ 解法（單卡特判）**：
```python
# player_data.py build_maxed_child
m.type = 7 if cid == init_hero_sys_id() else 1     # init_hero = 1001
```
**為什麼可行**（三個已證事實）：
1. `DataTable_config['init_hero'].value == 1001`
2. `CardModel.GetCardInfoById(id)` 按 **`card.id`** 查找（proto 0.46）
3. ⇒ 助理只查 `id=1001` 這一張卡 ⇒ 只有它需為 7；其餘 105 張保持 1 讓適格體列表非空

**走過的彎路（勿重蹈）**：
| 做法 | 結果 |
|---|---|
| 106 張全部 `type=7` | 助理 ✓ 恢復，但**適格體清單變空**（顯示「暫無適格體」） |
| 106 張全部 `type=1` | 適格體 ✓，但**助理白屏** |
| **只讓 `id=1001` 為 7** | ✅ **兩者皆正常**（使用者實測確認） |

**另註**：`CardModel.UpdateCardInfo`（proto 0.9）L46-53 用
`card.isHadRedPoint = (card.type == CardTypeIndex.Common)` —— **只影響紅點，不影響是否入列**。
（我一開始誤判它是「是否入列」的判定，導致推理繞遠路。）

### 0.5.12 🔴 嚴重踩坑：`_fill_required()` 會給 repeated 欄位自動補元素

#### 症狀

編隊界面「點 + → 選角色 → 確定」**完全無反應**（不報錯、界面不動）。
客戶端日誌固定崩在：
```
[SYS_EXCEPT] LuaException: ?:-1: attempt to index a nil value (field '?')
    ?: in field 'CompareToTempTeam'
    ?: in method 'OnMakeTeam'
    ?: in field 'TriggerEvent' → 'OnTeamViewCompleteMake'
```
服務端日誌：`15_2 cost_update_team` **一次都沒收到**（客戶端沒發）。

#### 根因（本專案自己的工具函式造成的）

`mock_game_server.py` 的 `_fill_required()` 對 **repeated message 欄位**有一條規則：

```python
if f.message_type is not None and getattr(f, "is_repeated", False):
    sub_required = [g for g in f.message_type.fields if getattr(g, "is_required", False)]
    if not sub_required:
        continue
    if len(getattr(msg, f.name)) == 0:
        elem = getattr(msg, f.name).add()      # ★★★ 自動補「一個」元素
        _fill_required(elem, depth + 1)
```

`15_4 cost_event_teams_s2c.children_team` **正是 repeated message**（元素是
`p_children_team`，內含 required 子欄位）⇒ 我們明明送的是**空清單**，
`_fill_required()` 卻**自動補了一個「最小合法元素」** ⇒ 客戶端收到一個
「假隊伍」⇒ `TeamModel.tempTeam` 結構不完整 ⇒ `CompareToTempTeam` 索引 nil。

**⇒ 這是本專案工具函式與「必須送空 repeated 欄位」場景的衝突。**

#### 修法

`_handle_15_4()` **空清單分支絕對不要呼叫 `_fill_required()`**：
```python
else:
    # ❗不要 _fill_required(m)：children_team 是 repeated message，
    #   _fill_required 會自動補一個元素 ⇒ 假隊伍 ⇒ 客戶端崩潰
    _send_msg(conn, 15, 4, m)
```
**repeated 欄位沒有 required 約束 ⇒ 空清單本來就能序列化**，無需補齊。

#### ⚠️ 通用教訓（**以後所有 handler 都要注意**）

| 場景 | 是否可用 `_fill_required()` |
|---|---|
| 想送**空 repeated 清單**（語意上「沒有資料」） | 🚫 **絕對不可用** —— 會變成「有一個假元素」 |
| required 純量/巢狀訊息缺值 | ✅ 可以用 |
| 想送**非空清單** | ⚠️ 慎用，只在確實需要補 required 子欄位時用 |

**判斷方式**：先問「這個 repeated 欄位空著是不是合法語意？」
* 是（如「沒有隊伍」「沒有加成」）⇒ **不要呼叫 `_fill_required`**
* 否（客戶端會 nil 迭代崩潰，如 `lottery_pool_s2c`）⇒ 才需要補

#### 編隊功能的最終狀態（2026-10-22）

| 重進保留 | ❌ **不可用** —— `15_4` 只能回空清單，否則客戶端必崩（3 次實測） |

**持久化為何放棄**：客戶端對 `p_children_team` 有反匯編描述檔沒列出的隱藏必填

> **规则**：`type` / `mode` / `state` / `code` 这类字段，
> **必须回配置表或 Lua 判断式确认正确值**，`1` 不是安全默认。

### 2.4b ⚠️ 更危险：id 字段被填充器挑到「别张表的 id」 `[REF]`

`_fill_required` 对 id 类字段会调 `real_id_for()`，挑一个**真实存在**的 id ——
但那可能是**别张配置表**的 id。

**实例**：`31_15` 的 `sys_id` 被填成 `1001`，那是 `DataTable_children` 的角色 id
（厄莉希），而客户端拿它去查 `DataTable_room_object` → 查不到 → `nil.type`
→ 崩溃 → 卡 85%。

> **规则**：**凡是客户端会拿去查表的 id 字段，都要写明确 handler 指定正确值**，
> 不要依赖通用填充器。不确定时，先看客户端的查表函数名（`GetXxxByKey`）
> 就知道该对应哪张表。

### 2.5 ⚠️ proto 类型对照表 `[REF]`

`p_building_center.power_speed` 类型是 **`int64`**，填 `0.0` 会抛
`TypeError: 'float' object cannot be interpreted as an integer`。

```
1=DOUBLE   2=FLOAT    3=INT64    4=UINT64   5=INT32
8=BOOL     9=STRING  11=MESSAGE 13=UINT32  14=ENUM
```

### 2.6 ⚠️ `host` 要用 `10.0.2.2`，不要用宿主机局域网 IP `[REF][实测]`

```
模拟器 eth0 = 10.0.2.15/24（QEMU user-mode NAT）

ping 10.0.2.2       → ✅ 0% loss (0.19ms)   ← 永远可达宿主机
ping 192.168.1.100  → ❌ 100% loss          ← 宿主机 WLAN 换 IP 后就死了
```
**`10.0.2.2` 是 QEMU NAT 固定网关，不受宿主机 WLAN 换 IP 影响。**

### 2.7 ⚠️ adb root 会破坏 `input` 命令 `[本区]`

`adb root` 让 shell 处于 `u:r:su:s0`，**SELinux 会拒绝 `/system/bin/input`**。
→ 用 `input tap` 前必须 **`adb unroot`**（回到 `u:r:shell:s0`）。

### 2.8 ⚠️ 日志检查必须核对 PID + 时间戳 `[本区][实测]`

本项目**多次因 logcat 旧记录误判**（我为此浪费 10+ 轮）：
- 清空后立即操作、立即读取，**核对 PID 是否当前进程**
- 计数用 `Select-String '^\[\d\d:\d\d:\d\d\]'`，**不要用 `Measure-Object -Line`**
  （日志含嵌入换行，一行 ≠ 一条）
- 客户端报错是**中文业务文案**，只 grep 英文关键词会全部漏掉

## 3. 协议规格 `[REF][APK]`（来自 `SNPacketData` 反汇编）

**证据来源**：`libil2cpp.so` (arm64) 反汇编
`SNPacketData.GenC2SPacket @ 0x1585D1C`、`ProcessS2CPacket @ 0x1585EE4`、
`SNBuffer.*`、`SNTCPClient.*`；以及 `global-metadata.dat` → `XorCode._passArr`

```
C2S: [u16 BE len = 总长-2][u16 BE uniq][u8 sId][u8 mId][body XOR passArr[(uniq+i)&0xFF]]
S2C: [u16 BE len = 总长-2][u8 sId][u8 mId][u8 zflag][body XOR passArr[((sId*16+mId)+i)&0xFF]]
       ↑ 两个方向 XOR 种子不同！
连线建立时客户端先送裸 2 bytes 01 02 → 必须丢弃，不可回送
zflag != 0 ⇒ body 是 zlib
```

**两条铁则**：
1. **`45_6 recharge_new_sync` 只回一次** —— 客户端收到回应会再送一次，
   每次都回会变成**无限 ping-pong**（实测 2773 次/秒 → 全黑）
2. **`26_2 scenario_enter_c2s` 没有 s2c** —— 它是通知型消息，不回是对的

**实现**：`server\lichter_wire.py`（含 256 字节 `PASSARR`、`FrameReader`、
`decode_c2s` / `encode_s2c` / `load_pool`），**自检 round-trip 通过** `[本区]`

## 6. 工作模式铁则 `[REF]`

1. **不要修改任何游戏文件** —— 不打 Lua 补丁、不改 `lua.ab`、不动 OBB 内容
   （唯一例外：`files/res/UrlList_Android.txt` 的 host，那是必要设定）
2. **不要用「回空清单」绕过问题** —— 和打补丁是同一种错误思路
3. **不要猜** —— 每个结论都要有源码行号或配置表依据
4. **一次一件事** —— 改完先说明，等用户确认
5. **用户操作时不要重启服务器** —— 会断他的 TCP 连线
   （本工作区踩过：擅自重启导致 `1_4` 登入失败）
6. **不要反复 `pm clear`** —— 会清掉用户进度

### 沟通要点 `[REF]`

- 用户要的是**结果**，不是过程。报告要**先讲结论**，再讲证据。
- 每个结论都要附**出处**（文件名:行号 / 配置表 / 日志时间戳）。
- **不要一次丢大量输出**。
- 卡住时**诚实说卡住**并要求做一个小实验，比继续猜有效。
- 用户的直觉常是对的。
