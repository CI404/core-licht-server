## 修復 #6 — `login_repeat_s2c`（`1_4`）回 `code=1` 導致登入失敗

| 項目 | 內容 |
|---|---|
| **症狀** | 遊戲重連時 `[LoginControl] 登入出錯 isForceExit=false`<br>`log=[LoginGameServerControl] On_1_4 #QR系统邏輯錯誤#n` → 連線立即關閉 |
| **證據** | 抓包 `1_4` body = `0801` → `code=1`；客戶端印 `Receive 1_4 code=1` |
| **根因** | `_generic_reply()` 的**執行順序**錯誤：<br>`m.code = 0`（先設成功）→ `_fill_required(m)`（後執行，把 `code` 覆寫成保守值 `1`）<br>而 `_fill_required` 對「非 `*_id` 的整數 required 欄位」一律填 `1`，`code` 正好符合 |
| **修法** | 把 `_fill_required(m)` 提到前面，**最後**才明確覆寫 `m.code = 0` |
| **影響範圍** | **所有走通用回應器且帶 `code` 欄位的 s2c** —— 全部從 `1`（失敗）變成 `0`（成功） |
| **驗證** | 修復前 `hex=0801`（code=1）→ 修復後 `hex=0800`（code=0），登入成功 |

## ⚠️ 第三重要：`host` 要用 `10.0.2.2`，不要用宿主機區網 IP

實測（2026-10-10）：

```
模擬器 eth0 = 10.0.2.15/24（QEMU user-mode NAT）

ping 10.0.2.2       → ✅ 0% loss (0.19ms)   ← 永遠可達宿主機
ping 192.168.43.7   → ❌ 100% loss          ← 宿主機 WLAN 換 IP 後就死了
```

**`10.0.2.2` 是 QEMU NAT 的固定閘道，不受宿主機 WLAN 換 IP 影響。**
用 `nc` 從模擬器實測：

```
nc 10.0.2.2 8080   → HTTP/1.1 200 OK
nc 10.0.2.2 9001   → PORT OK
```

> 若哪天 `10.0.2.2` 不通，先確認 CDN 有綁 `0.0.0.0`（不是 `127.0.0.1`）。

## 協定規格（供日後維護參考）

```
C2S: [u16 BE len = 總長-2][u16 BE uniq][u8 sId][u8 mId][body XOR passArr[(uniq+i)&0xFF]]
S2C: [u16 BE len = 總長-2][u8 sId][u8 mId][u8 zflag][body XOR passArr[((sId*16+mId)+i)&0xFF]]
連線建立時客戶端先送裸 2 bytes 01 02 → 必須丟棄，不可回送
zflag != 0 ⇒ body 是 zlib
```

**兩條必須遵守的伺服器規則**：
1. **`45_6` 只回一次** —— 客戶端 handler 收到回應會再送一次，每次回會變成無限 ping-pong（實測 2773 次/秒 → 全黑）
2. **`_fill_required` 的陷阱** —— 對 `type` / `mode` / `state` 這類**帶語意的列舉**欄位不能亂填保守值 `1`（修復 #2 就是踩到這個）
